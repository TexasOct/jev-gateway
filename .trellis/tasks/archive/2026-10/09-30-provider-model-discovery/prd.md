# 上游模型发现与策略模型衔接

## Goal

让用户获取所配置上游的模型列表，并将需要的模型用于分流策略，减少复制模型 ID 的操作。对应父任务 R3、R7。

## Background

- 父任务：`.trellis/tasks/09-30-provider-configuration-experience`。
- 上游列表格式与认证不统一，不能把所有 provider 都当作 OpenAI `/v1/models`。
- 模型列表并不普遍提供完整的能力、价格或上下文信息，发现模型不等于已经验证路由能力。

## Requirements

- M1: 获取当前受支持上游类型的可用模型，明确可支持与不支持的发现类型；模型项携带安全的上游 ID 和已证实的元数据来源。
- M2: 使用当前 provider 的 endpoint 与凭证，不在浏览器直接请求上游，不在 URL 或读响应中暴露密钥。
- M3: 列表支持搜索、去重与分页/完整性提示，发现超时或失败可重试，缺少列表接口可手动添加。
- M4: 刷新不能删除已配置模型、重置用户编辑的能力/标签/优先级，或使策略引用失效。
- M5: 有效目录模型使用 `provider/upstream_model`；不同 provider 的同名模型分别保留。
- M6: Decision 的评估 endpoint 不自动套用 LLM 列表协议。不支持模型发现的 System One provider 仍允许显式填写模型或保持原有可省略语义。
- M7: 控制发现请求的时间、响应大小、分页、并发与缓存边界；取消和 provider 变更不能让旧结果覆盖新结果。
- M8: 采用用户确认的选中导入流程：发现后搜索/勾选，支持明确范围的全选，显式确认后仅导入选中模型。发现、刷新和取消本身不得写入有效路由目录。
- M9: 新模型导入前补齐或显式确认必要的价格与能力元数据，可信来源可预填且支持批量设置；不静默使用未知能力/价格的默认值，不改变旧配置默认语义。
- M10: 调查并定义在线元数据查询来源，保留来源、适用服务商、单位和时间信息；无精确匹配、来源冲突、缺失或查询失败时允许手工补齐。已确认值不因刷新自动改写。
- M11: 配合已授权的模型存储结构优化，将来源数据与用户确认的有效路由值分开；不以公共目录覆盖当前账户的服务限制或价格，不新增另一份运行时模型目录。
- M12: 用户确认显式开启后支持 localhost/私网发现；默认拒绝私网，危险目标和重定向仍拒绝。

## Acceptance Criteria

- [x] ACM1 (M1, M2): 受支持类型的成功、错误认证和上游异常通过 mocked HTTP 验证，不发送真实上游请求。
- [x] ACM2 (M3): 分页、重复 ID、空列表、列表不完整、超时和不支持分别产生可辨识状态，仍可手动添加。
- [x] ACM3 (M4, M5): 刷新、重新获取与重复选择不破坏现有模型、标签和策略；相同上游 ID 在不同 provider 下不会碰撞。
- [x] ACM4 (M6): System One 的模型输入语义不被 LLM 自动发现改变。
- [x] ACM5 (M2, M7): 日志/错误/响应/缓存不泄露 key；无效 URL、跨 origin 重定向、过大响应和旧请求竞态受测试覆盖。
- [x] ACM6 (M8): mocked 发现/刷新/取消后 catalog 字节与运行时模型目录不变；单选、多选和全选只导入用户确认的模型，未选结果不会进入策略模型选择器。
- [x] ACM7 (M9, M10): 缺少必要元数据时导入被阻止；可信预填与逐项/批量确认可完成导入。源字段缺失、价格单位换算、provider 对应关系、来源冲突和手工值保护有独立测试，不能把原厂价格当成自定义服务商的实际价格。

验收证据：主端 82 个发现/network/metadata tests，4 个 HTTP onboarding integration，以及 43 个 Provider browser cases。独立 review 的 native structured-output→JSON mode 和短 Content-Length 两条 P2 已修正并读回复验；含私网候选、参考-only 输入 limit、原单位、规范 envelope 与明确导入。详见父任务 `acceptance.md` 和 child `implement.md`。任务状态保留 in_progress，未提交或归档。

## Dependencies and Boundaries

- 先确认 `09-30-provider-profile-config` 的 provider 身份、类型和凭证契约，再集成发现功能；可先做无网络 fixture 研究。
- 不更改策略算法，不按模型名称猜测能力，不用生成请求试探模型能力或产生额外推理费用。
- 浏览和表单实现属于 `09-30-provider-library-onboarding`；本任务拥有发现契约与模型目录一致性。
