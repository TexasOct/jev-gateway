# Provider 展示元数据与统一配置契约

## Goal

让预设、自定义表单和现有配置编辑器保存同一份 provider 配置，支持品牌与展示信息，并优化本次功能所需的模型存储；保持 decision 与 LLM 的运行时职责分离。对应父任务 R1、R2、R5、R7、R9。

## Background

- 父任务：`.trellis/tasks/09-30-provider-configuration-experience`。
- 现有 decision 配置明确使用 `protocol: "system_one"`；品牌、实例 ID、协议和模型不可混为一个字段。
- 当前 Settings 的主题与语言使用独立存储，不能并入 provider 配置。

## Requirements

- P1: 两类 provider 支持可编辑显示名称、稳定实例 ID 和图标选择；已知供应商品牌标识与实例名称分离。
- P2: 预设仅辅助初始字段填充，保存后通过现有配置校验/读写链路生效；更改预设不能静默覆盖用户已编辑的字段。
- P3: LLM 自定义表单支持当前已注册的传输类型及 endpoint；decision 自定义表单显式选择当前已注册的协议，System One 必须可选。
- P4: 旧配置没有新增展示字段时仍可读取，并获得安全的默认名称/图标回退。
- P5: 凭证读写沿用当前声明的配置/密钥机制；读 API、发现结果、快照与日志不返回明文密钥。
- P6: 展示信息更改不重命名 provider ID、不改变传输协议，也不破坏 `provider/upstream_model` 引用。被模型或策略引用的删除/改名应受到校验。
- P7: 用户允许优化模型存储结构以便接入价格与能力查询。区分模型规格、提供方服务配置、报价及用户确认值，保留单一规范配置来源，明确缺失/冲突/确认状态和来源时间。
- P8: 结构优化须提供旧配置读取、无损迁移和失败回滚契约；不因加入在线数据源而自动改写既有路由值或改变旧配置默认语义。

## Acceptance Criteria

- [x] ACP1 (P1, P4): 无展示字段的旧配置与包含自定义名称/图标的新配置都能保存、重载和正确显示。
- [x] ACP2 (P2): 预设和自定义输入生成同样的规范配置，无额外运行时来源；手工修改不会因预设切换丢失。
- [x] ACP3 (P3): decision 协议选项来自受支持类型，System One 可选，未知协议被拒绝；LLM 类型不通过品牌推断。
- [x] ACP4 (P5): 保存、读取、错误、快照和日志的 hostile-secret 用例没有明文泄露。
- [x] ACP5 (P6): 修改显示名称和图标后模型 ID 与策略引用保持不变，非法删除/改名不会替换有效配置。
- [x] ACP6 (P7, P8): 新结构可表示提供方相关价格、模型规格和逐字段确认，旧目录迁移前后模型 ID、策略引用和路由输入一致；混合/不兼容格式、迁移冲突及写失败不替换有效目录。

验收证据见父任务 `acceptance.md`：原六项独立审查问题经 14 个事件/故障注入回归修复；追加 CLI literal-consumer P2 经 15 个新回归关闭，主端已读回源码。最终全量 719 tests、Pyright 零诊断、210 frontend units / 80 browser、最终 wheel/sdist 均通过。旧语义、共享引用、有效 inherited presence、未恢复 journal 的读屏障与 healthy runtime 保留均有证据。任务状态保留 in_progress，未提交或归档。

## Dependencies and Boundaries

- 与 `09-30-unified-settings-provider-config` 衔接，优先复用已实现的 provider 存储；不重复创建 Settings 或搬移主题/语言。
- 模型发现子任务消费本任务确认后的 provider 身份与凭证契约；界面子任务消费展示元数据与规范保存接口。
- 模型存储结构和元数据字段由本任务定稿，与模型发现子任务核对来源及单位；在线数据源抓取和匹配仍由发现子任务负责。
- 不实现上游模型发现、不添加 decision 新协议、不修改路由算法。
- 用户已明确要求实施；按技术方案先交付配置底座，再集成模型发现与界面。
