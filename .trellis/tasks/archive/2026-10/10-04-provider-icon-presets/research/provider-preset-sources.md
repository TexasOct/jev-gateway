# Provider preset sources

Reviewed against installed LiteLLM 1.102.0. The active-task resolver returned `none`; the caller explicitly supplied this existing task directory, so research stayed under it. No product code or tests changed.

`null` means the native transport supplies the URL or no bearer key is required. `""` means the user must supply a URL. Environment names are proposed explicit credential references; JEV resolves them before calling LiteLLM. Regional names keep credentials separate. Aliases support search and do not assert model availability.

The regional and global evidence files linked below contain fetched official references and installed transport paths. The table consolidates their reviewed recommendations. Rows with verification limits say so explicitly.

## Cloud configuration and CLI limits

Azure requires the real resource endpoint and deployment name. Put a deliberately selected `api_version` in `params`; installed LiteLLM defaults to `2025-02-01-preview`, but this default does not establish compatibility with every deployment. An Entra token belongs in `param_env.azure_ad_token`, never literal `params`. A preset can use the API-key path initially and explain the alternative.

Vertex accepts `params.vertex_project` and `params.vertex_location`; the location must support the chosen model. Credentials use ADC (`gcloud auth application-default login` or `GOOGLE_APPLICATION_CREDENTIALS`) or `param_env.vertex_credentials` referencing a JSON string/filepath. Installed transport also reads `VERTEXAI_PROJECT`, `VERTEXAI_LOCATION`, `VERTEXAI_CREDENTIALS`. Keep `api_base=null`: LiteLLM constructs the regional or global endpoint from supplied configuration. Do not invent a project or region.

Bedrock needs `params.aws_region_name` or `param_env.aws_region_name`; ambient `AWS_REGION_NAME`/`AWS_REGION` are also recognized. AWS credentials may come from the AWS chain/profile/role. Explicit credentials belong in `param_env.aws_access_key_id`, `param_env.aws_secret_access_key`, and optional `param_env.aws_session_token`. Optional non-secret parameters include `aws_profile_name`, `aws_role_name`, `aws_session_name`; `aws_web_identity_token` belongs in `param_env`. Current official LiteLLM docs also describe Bedrock bearer API keys via `AWS_BEARER_TOKEN_BEDROCK`/`api_key`; the baseline template should use IAM unless that path receives a separate installed-transport review. Leave URL native and require the actual region and model/inference-profile identifier.

JEV `catalog.py` accepts `params`/`param_env` dictionaries, validates Python-identifier keys, rejects reserved `model`, `messages`, `stream`, `api_base`, `api_key`, and prevents overlap. Secret-like parameter names belong in `param_env`. These values flow through resolved provider parameters to LiteLLM in `gateway.py`. The current CLI offers only OpenAI, Anthropic, DeepSeek and custom; custom requires URL/key-env and has no `params`/`param_env` flags. Cloud presets cannot become fully configurable merely by widening that enum. The shared registry needs setup metadata and a CLI path for these fields or a precise instruction to complete the configuration file. Local native presets also need optional credentials and private-network discovery support.

## Scope choices and evidence limits

- Native types take precedence where installed: `cohere_chat`, `ollama_chat`, and `lm_studio` are intentional. Confirmed compatible services without native types use `openai`.
- Hunyuan uses its documented compatible API. Installed `tencent` points to TokenHub; using that type would select another service.
- Baichuan's official page loads API YAML through a public documentation endpoint. That YAML verifies `https://api.baichuan-ai.com/v1/chat/completions`, OpenAI compatibility and bearer authentication. See `baichuan-api.md` for the request contract and extracted evidence.
- ModelScope has a usable installed native path at `https://api-inference.modelscope.cn/v1`; its vendor page needs browser follow-up. MiniMax regional endpoints are confirmed by installed transport and LiteLLM docs. Cloudflare and LM Studio vendor fetches returned 403; official LiteLLM docs and installed transport supplied their setup evidence.
- `null` native defaults are version-dependent. Preserve DeepSeek's explicit stable URL. Account/project/region values stay operator input. No live inference requests or account-access checks were made.

## Parent integration update

The parent reports that CLI preset choices are now dynamic and supports `--param NAME=VALUE` and `--param-env NAME=ENV` through existing catalog validation. The CLI limitations above describe the inspected baseline and have been addressed by that implementation. `ProviderPreset` now supports `aliases`, `docs_url`, bilingual setup instructions, and declared `setup_fields` with `params`/`param_env` targets. No integration tests were run by this research agent.

Declare Azure `api_version` as a required `params` setup field and its actual endpoint as required provider URL input. Declare Vertex `vertex_project` and `vertex_location` as required `params` fields, with optional `vertex_credentials` targeting `param_env` for users who do not use ADC. Declare Bedrock `aws_region_name` as required `params`, with optional `aws_access_key_id`, `aws_secret_access_key`, and `aws_session_token` targeting `param_env`. Explain role/profile authentication in setup instructions. Credential fields remain optional individually because ambient identity can supply credentials; instructions should require a complete credential path. Do not supply a fabricated account endpoint, project, or region.
