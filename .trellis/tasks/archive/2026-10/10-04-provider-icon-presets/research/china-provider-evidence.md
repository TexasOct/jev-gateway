## Installed evidence and review limits

Package root: `.venv/lib/python3.14/site-packages/litellm/`. `types/utils.py` registers `dashscope`, `qwencloud`, `qwen_ai_platform`, `moonshot`, `zai`, `minimax`, `volcengine`, `modelscope`, and `tencent`. It has no standalone `baichuan`, `yi`, `siliconflow`, `hunyuan`, `spark`, `stepfun`, or `qianfan` values. Those confirmed OpenAI-compatible services use registered `openai`.

Relevant transport files:

- `llms/dashscope/chat/transformation.py`: China compatible endpoint, `DASHSCOPE_API_KEY`; `llms/dashscope/qwencloud.py`: international endpoint. Both accept explicit base override.
- `llms/moonshot/chat/transformation.py`: `.ai` native default, `MOONSHOT_API_KEY`, explicit base override.
- `llms/zai/chat/transformation.py`: global default, `ZAI_API_KEY`, OpenAI-compatible chat transform.
- `llms/minimax/chat/transformation.py:17`: international and China endpoints; international default.
- `llms/volcengine/common_utils.py`: Ark root. An explicit base should be the transport root, not an OpenAI `/v1` path.
- `llms/modelscope/chat/transformation.py:25`: ModelScope default and `MODELSCOPE_API_KEY`.
- `llms/tencent/chat/transformation.py:119`: **installed default is `https://tokenhub-intl.tencentcloudmaas.com/v1`**, while current LiteLLM docs show `https://tokenhub.tencentcloudmaas.com/v1`. Neither is Hunyuan. Avoid using `tencent` for the Hunyuan preset.

All source pages above were fetched. ModelScope and MiniMax vendor pages returned client-rendered shells; their installed transports establish the stated defaults. Baichuan's underlying official API YAML supplied direct endpoint and compatibility evidence. Failed exploratory paths (`providers/volcengine`, `providers/modelscope`, StepFun English quickstart) were replaced where a working reference was found. No live vendor inference requests were sent. Base URL evidence confirms protocol/setup, not account access or model availability.
