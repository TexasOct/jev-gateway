- `litellm/main.py:3023` uses Cohere v2 chat; `:3028` uses legacy v1 chat. `:3147` accepts `HF_TOKEN`.
- `litellm/llms/huggingface/chat/transformation.py:24` defines the router host. The native adapter resolves provider mappings; do not replace it with a guessed model endpoint.
- `litellm/llms/cloudflare/chat/transformation.py:49` derives the account URL and rewrites legacy `/ai/run` to `/ai/v1`. `litellm/main.py:4446` accepts the token. Passing a fictitious account URL would make the template look usable without an account.
- `litellm/llms/lm_studio/chat/transformation.py:16` reads `LM_STUDIO_API_BASE`; its key defaults to an empty string. Registered `lm_studio` avoids JEV's mandatory key restriction on `openai`.
- `litellm/litellm_core_utils/get_llm_provider_logic.py:685` and `litellm/llms/deepseek/chat/transformation.py:350` default to DeepSeek `/beta`. The preset should retain the stable `/v1` endpoint confirmed by DeepSeek's official quickstart.

## JEV requirements and CLI limitations

`jev_gateway/catalog.py:968` requires a resolved key and URL for `type=openai`. Native Ollama and LM Studio allow keyless local service configuration. Set `allow_private_network=true` for local/private discovery, and make the address reachable from the gateway process. Native transport availability does not guarantee that every provider supports JEV's model-discovery operation.

The existing CLI only accepts `openai`, `anthropic`, `deepseek`, or `custom`; `custom` requires URL and credential-env flags. It has no `params` or `param_env` flags. A shared preset registry needs CLI choices and optional credentials to follow the selected native type. Blank template addresses must remain an incomplete form value until the operator supplies them, because saved catalog URLs cannot be empty.

## Verification limits

Official LiteLLM `.md` pages were fetched for every row. They document native provider routes, key names, and vendor references. Direct fetches of Cloudflare and LM Studio vendor pages returned HTTP 403; the listed account URL and native LM Studio requirements were checked in installed transport and official LiteLLM docs. No live credentials, billable requests, or model-availability checks were used. Online docs may describe features newer than installed 1.102.0; the installed provider registry and transport win for type/default decisions.
