# 自动网关重启设计

## 范围与目标

Release wheel 安装器更新完成后，若目标 `--home` 下原本存在由 JEV CLI 管理且所有权可验证的运行中网关，则重启网关并等待健康检查。全新安装或网关原本未运行时不启动服务。该逻辑只适用于 Release wheel 分支，且 `--no-init` 不跳过重启。

## 架构边界

- `scripts/install.sh` 负责安装协调和版本资产校验，不自行解析 PID 文件或发送信号。
- 所有进程识别、所有权校验、停止和启动行为放在 `jev` CLI 进程管理层。
- 继续使用 `RuntimePaths` 和既有 `process.py` 的 token、命令行、home 匹配校验。
- Release 安装器在 wheel 安装成功后调用新版本 CLI 的“仅运行时重启”路径，传入与安装相同的 `--home`。
- 调用点位于 Release wheel 安装成功之后、独立于 `install init` 条件之外。这样 `--no-init` 会跳过配置初始化但不跳过运行中服务重启。
- `--ref` 安装、本地安装脚本、Docker、launchd/systemd 与前台外部进程不在范围内。

## 重启行为契约

1. 先检查该运行目录是否有经 CLI 所有权校验确认的运行中进程。
2. 如果没有运行中的受管理网关，返回明确的 no-op 结果，不启动新进程。
3. 如果 PID 文件对应进程存在但所有权无法确认，不向该 PID 发信号，不尝试启动可能冲突的第二个网关，并返回可操作错误提示。
4. 对确认归属的进程，沿用现有安全停止流程；停止超时则失败，不继续启动新进程。
5. 停止成功后启动新版本，复用 `jev start` 的健康探测逻辑，最多等待 10 秒。
6. 健康检查通过才报告重启成功；启动或健康检查失败、超时均返回非零错误。
7. 安装失败、wheel 校验失败、dry-run 和源码 `--ref` 路径不触发自动重启。

## 兼容性与数据

自动重启复用现有运行目录，不改写 `models.json`、`.env` 或记录数据库。`install init` 继续保留已存在配置。PID 所有权验证规则不放宽。

## 运维与回滚

自动重启失败时安装器以非零状态结束并告知程序包已更新但服务未能恢复，提供手动 `jev start` / `jev status` 提示。安装器不自动回滚 wheel，因为配置和新旧版本兼容性无法安全推断。用户可通过固定旧版本 Release 安装脚本回退，然后检查配置与日志。
