# Dashboard 与文件配置的只写密钥管理

## Goal

用户可以在 Dashboard 输入密钥完成初始化配置，保存后仅查看配置状态，不能读取已有密钥。纯服务端部署可通过配置文件完成相同配置，无需浏览器或导出进程环境变量。

## Requirements

- R1: Dashboard 支持 LLM 和 decision 提供方密钥的初始化、保留、替换和清除；输入后完成持久化并供运行时使用。
- R2: Dashboard 的读取、校验、保存响应和配置展示均不返回已存密钥；输入值只在当前提交过程中存在，完成或取消后清空，不写浏览器持久化存储。
- R3: 文件配置支持 LLM、decision 和入站网关鉴权的密钥，纯服务端启动、校验及重载可使用该配置。明确文件格式、路径和冲突规则。
- R4: 保持既有 api_key_env、.env、CLI 和路由配置兼容；所有入口使用一致的有效凭据解析，不临时修改进程环境。
- R5: 初始化、配置变更和无密钥/错误密钥状态有可理解的界面和错误反馈；现有配置写入鉴权、并发版本检查和失败回滚继续有效。
- R6: 文件中的密钥不会通过公共配置快照、历史记录、错误或日志回显；本地持久化和恢复材料使用已有受限权限机制。
- R7: 文档给出网页初始化和纯服务端配置的可执行示例，说明密钥不回显、替换/清除语义及环境配置兼容。

## Acceptance Criteria

- [x] 在隔离的默认安装中，通过浏览器输入密钥、保存、刷新并确认运行时可使用该密钥，已有密钥字段始终为空。
- [x] LLM 与 decision 密钥设置、替换、保留、清除均通过真实配置事务测试；失败或冲突不改变磁盘和健康运行时。
- [x] 仅提供配置文件即可启动纯服务端，入站鉴权、LLM transport 和 decision transport 均使用预期凭据；重启及重载保持有效。
- [x] 环境配置兼容、配置来源冲突、缺失/无效输入和共享凭据引用有明确且经过测试的行为。
- [x] 读取、校验、保存、策略/模型快照及新记录、错误和日志均不包含测试密钥；浏览器 URL、cookies、localStorage、sessionStorage 不含密钥。
- [x] 全量 Python 测试、Pyright、前端 lint/unit/build、相关浏览器测试及包含新配置行为的安装包检查通过。
- [x] README 双语入口、配置/API/安装文档和相关规范与实现一致。

## Scope

本任务修改密钥配置和消费边界，复用现有 Provider 管理界面及配置事务。远程发布、云端密钥库、上游账户登录和其他 Settings/图标任务不属于此次交付。

## Authorization

用户当前 Goal 明确要求自主实现和验证完整目标；任务创建、规划及实现按该授权推进。规划先落盘，再激活任务。
