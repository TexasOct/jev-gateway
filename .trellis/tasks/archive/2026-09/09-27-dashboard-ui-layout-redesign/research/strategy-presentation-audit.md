# Strategy presentation audit

## Scope and evidence

The strategy editor already has a full-height graph, measured inspector, and measured bottom drawer. The advanced editors live in `<details className="workflow-advanced">` within `.workflow-info`, not on the graph itself (`frontend/src/config/RoutingEditor.tsx:576-758`). The design-language brief asks for a restrained operator-console hierarchy, existing palette tokens, legible 13px controls and 12px supporting text, quiet 8px panels and 6px controls, while retaining the dotted graph, node types, tools, inspector, and drawer (`research/design-language.md:15-47`; canonical visual study: `.trellis/tasks/archive/2026-09/09-27-dashboard-visual-language/research/style-spec.md`).

Current advanced-view CSS is sparse: `.workflow-advanced` has a margin and its `summary` uses muted text (`frontend/src/styles.css:900-901`). The drawer contains four disclosures: fallback/workflow overview, advanced editors with sortable rule rows and model pools, saved pool order, and pending changes. Rule rows, zones, and chips already have surface/border styles (`styles.css:996-1110`); global control/focus styles are established at `styles.css:784-802`. This leaves the disclosure headings, secondary descriptions, dense row text, and read-only table visually close in priority to the editable controls.

## Targeted change proposal

- Scope presentation rules to `.workflow-info .workflow-advanced > summary`, `.workflow-info .workflow-advanced > h3`, `.workflow-info .workflow-advanced > .meta`, and `.workflow-info .workflow-advanced .empty`. Give summaries primary-text contrast, 13px medium weight and a visible focus treatment; section headings 14px medium weight; descriptions and empty copy 12px with readable muted contrast. Keep native `details` semantics and content order.
- Within the expanded advanced editor, use `.workflow-advanced .rule-condition`, `.workflow-advanced .rule-index`, `.workflow-advanced .zone h4`, `.workflow-advanced .chip-handle`, `.workflow-advanced .chip-tags`, and `.workflow-advanced .chip-priority` for type weight/color hierarchy. Distinguish rule conditions and model names from secondary tags and indices. Retain wrapping for long condition/model strings and leave drag handles recognizable. If adding borders or backgrounds to `.rule-row`, `.zone`, or `.chip`, change color only; avoid padding, grid, width, min-height, margin, or border-width adjustments that alter DnD hit boxes and sorting feedback.
- Preserve the existing disclosure/group layout and read-only `.table-wrap` overflow. A scoped table treatment such as `.workflow-advanced .table-wrap th` and `.workflow-advanced .table-wrap td` may improve header/value contrast without changing cell padding, width, row height, or the existing mobile `data-label` presentation. Keep `.workflow-advanced .diff` readable for pending changes without changing review or save state.
- Use only `--surface`, `--surface-alt`, `--border`, `--text`, `--text-muted`, `--accent`, and existing semantic tokens for their actual status meaning. Check selected/hover/disabled/focus contrast in both themes and English/Chinese at narrow widths. Do not use category colors as decoration, add motion, or shrink touch targets to fit text.

## Hard no-touch areas

- Canvas geometry and coordinates: `.routing-canvas-scroll`, `.routing-canvas-board`, `.routing-canvas-content`, `.routing-canvas-node` dimensions/position/padding/border widths, `.canvas-node-content` row sizing, `.canvas-marquee`, SVG handles and paths, and `node-card.ts` / `canvas.ts` constants (`styles.css:387-489`; `RoutingCanvas.tsx:577-633`). No CSS transforms on interactive canvas objects.
- Measured overlay boxes and chrome: `.workflow-inspector`, `.inspector-body`, `.workflow-drawer`, `.workflow-drawer-heading`, `.workflow-info`, `.workflow-toolbar`, `.canvas-tools`, `.workspace-chrome`, their breakpoint layouts, heights, padding, overflow, positioning, and z-index (`styles.css:400-416, 863-985`). `RoutingEditor.tsx:362-380, 566` places the inspector from available canvas space; `RoutingCanvas.tsx:108-137` measures chrome and reports node anchors. Avoid visual changes that enlarge their bounding boxes, including added outer borders or box shadows that interfere with legibility.
- DnD and behavior: `.handle`, `.chip-handle`, `.rule-row`, `.chip`, `.zone.over` hit areas and cursor/touch affordances; inline transforms in `RuleRow` / `ModelChip` (`RoutingEditor.tsx:113-119, 203-212`). Leave keyboard/Escape paths, selection, drawer expansion, and all API validation/apply/reset or layout persistence logic unchanged (`RoutingEditor.tsx:477-513, 553-770`; `RoutingCanvas.tsx:148-178, 266-296, 520-575`).

This is a read-only audit. No frontend files were changed, and no server or build was run.
