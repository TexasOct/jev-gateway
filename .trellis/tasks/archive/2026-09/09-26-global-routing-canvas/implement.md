2. Extend the existing changes in `App.tsx`, `RoutingEditor.tsx`, `RoutingCanvas.tsx` and scoped CSS to fill the viewport below the actual shared header. Replace the nested padded card and fixed board height with one canvas surface. Move strategy title/status/warnings into compact workspace overlays and consolidate all lower sections and review controls into a bounded bottom drawer. Do not change monitoring/appearance layouts. Keep advanced controls inside their DnD provider and preserve the draft/validation/review/apply lifecycle.
3. Update selected-node viewport reporting, Fit/reveal and inspector placement for the new workspace, drawer and overlay bounds, header wrapping, drag, scroll, zoom and resize. Constrain panel size and internal scrolling; avoid covering all draggable node area on narrow screens. Preserve existing selection and focus behavior.
4. Make the toolbar add-rule action enter the existing rule creation workflow. Implement only supported canvas modes; ensure mode changes and canvas movement do not mutate routing policy.
5. Improve node dragging as layout-only interaction: suppress selection-driven reveal while pointer capture is active; keep group offsets, cancel/rollback and keyboard displacement consistent through zoom and pan. Add focused tests and real-browser evidence for pointer capture, hit testing, PUT payloads and reload at nonzero viewport.
6. Render role-specific question/rule/fallback/label/model cards with visible type label, simple inline icon/shape, concise summary and restrained token-based color/border differences. Keep 190px node bounds/ports/selection/focus behavior and readable long labels, with English and Chinese role text. Test DOM structure and light/dark variants.
7. Preserve independent canvas-layout API behavior. Add or update frontend tests for panel position/clamping, toolbar modes, add-rule flow, tray defaults and persistence isolation. Add backend tests only if the existing persistence boundary changes; the design expects no API/schema changes.
8. Add paired English/Simplified Chinese strings and responsive/focus styling.
9. Run `npm --prefix frontend run lint`, `npm --prefix frontend run test`, `npm --prefix frontend run build`, `scripts/build-frontend.sh --check`, focused backend tests (`uv run pytest tests/test_canvas_layout.py tests/test_gateway.py tests/test_routing_overlay.py tests/test_routing_strategies.py`), then the full `uv run pytest -q` and `uvx pyright` final checks.

Measure that the canvas uses the viewport remainder below the shared header, that drawer expansion remains inside it, and that monitoring/appearance are unchanged. Check: toolbar operation and keyboard mode switching, adding a rule, selecting/dragging a node, inspector anchor behavior at each canvas edge, inner scrolling, closing/reopening details, bottom tray expansion, and restored layout. Inspect screenshots and captured requests; prove node movement writes only layout and policy changes still use the existing validation/apply flow.

Record any unrelated full-suite installer failures separately rather than modifying release files. Review the complete diff against this PRD/design, with special care not to stage or commit unrelated existing work.
