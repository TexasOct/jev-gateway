# Installer and local contract

## What exists

- The documented entry command fetches `scripts/install.sh` from raw `main`, in `README.md:30`, `README.zh-CN.md:27`, `docs/cli.md:10`, and `docs/local-install.md:25`. The fetched script is therefore mutable even if its package source is later pinned.
- `scripts/install.sh:4-20` defaults to `${JEV_INSTALL_REF:-main}` and accepts `--ref`, `--home`, `--no-init`, `--dry-run`, `--yes`, and `--no-uv`. It supports Darwin and Linux, checks or bootstraps `uv`, then sets `source="git+https://github.com/TexasOct/jev-gateway@$ref"` and calls `uv tool install --force "$source"` (`:22-55`). When initialization is enabled, it invokes `jev install init --home ... --ref ... --method isolated` (`:56-58`). Dry-run prints those commands without installing. `set -eu` is present; the `uv` bootstrap is downloaded to a temporary script before execution (`:1-2`, `:39-45`). There is no release lookup, wheel download, digest check, or explicit missing-release handling.
- `jev_gateway/cli/main.py:76-81,221-226` accepts `install init --ref` with default `main`; `jev_gateway/cli/install_state.py:16-23,43-59` preserves existing runtime templates but writes state `ref` and a *synthesized git source* for that ref. Installing a wheel without changing this contract would leave inaccurate provenance. `jev_gateway/cli/main.py:240-249` hard-codes `jev --version` to `0.1.0`.
- `tests/test_install_script.py:8-19` has one stub-uv dry-run test asserting `git+https://github.com/TexasOct/jev-gateway@main`. Related template and preservation checks are in `tests/test_cli_templates.py` and `tests/test_cli_install_state.py`. The old test must change if the default becomes a release artifact. Network-free tests should cover release resolution, asset/digest mismatch, missing latest release, explicit version/ref behavior, and install-state provenance; the current dry-run contract needs a defined meaning when resolution would require network access.
- `docs/local-install.md:25-30` promises reruns preserve `models.json`, `.env`, and records. `docs/cli.md:69-79` promises uninstall preservation by default. The prior curl task PRD explicitly excluded release tags and published wheels (`.trellis/tasks/09-24-curl-install-and-cli/prd.md`, Out of scope), so this task owns release integration, not the earlier task.

## Boundaries to preserve

Keep the CLI as the runtime initializer: release resolution and package acquisition belong to the installer, while `jev install init` owns template creation and state. Align actual installed source with the state `source` field rather than merely passing a release tag as `--ref`. Preserve POSIX `sh`, macOS/Linux scope, `uv` bootstrap consent behavior, no-clone UX, and the install-state/uninstall safety contract in `.trellis/spec/backend/cli-lifecycle.md`. Update both READMEs in lockstep per `.trellis/spec/backend/index.md`.

The current script constructs a git URL from unchecked `--ref`; an implementation should distinguish a trusted release tag or asset URL from an arbitrary user-supplied ref, and keep every interpolated value quoted. If install verification is selected, the retrieved checksum needs a trusted source tied to the same immutable release as the artifact. This is a design decision, not existing behavior.
