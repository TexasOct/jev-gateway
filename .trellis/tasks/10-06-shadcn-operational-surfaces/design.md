# Operational surfaces design

Own monitoring and routing presentation at the parent migration-map paths. Keep data/query/draft admission and asynchronous ownership in their current modules; shared primitives only render controls and states.

Monitoring uses shared panel headings, Badge/Alert feedback and applicable Tabs/disclosure controls. Preserve fixed session/request virtual rows at 132px/360px and their breakpoint-specific windows, all height constraints, overscan and focused-row retention. Expanded evidence must fit within its established scroll container. Recorded evidence remains distinct from live activity.

Workflow uses common buttons/native fields, menu skin and semantic node tokens. Keep existing context-menu target draft ownership and inverse coordinates, protected/generated actions, measured occlusion, selected-node exposure, DndContext descendants and serialized layout writes. Current node metrics, SVG viewBox and dynamic coordinates stay with the common graph/metric owner.

No new generic menu library may replace a canvas coordinate/target contract merely for appearance. Toolbar/inspector/drawer layout changes are measured against available canvas area and existing mobile/tall-view tests. History/reset/remount and stale-operation guards remain intact.

Acceptance checks actual native pointer/keyboard/scroll interactions and computed geometry, with screenshots in both locales/schemes. Marker classes or synthetic PointerEvent dispatch alone cannot prove hit testing.
