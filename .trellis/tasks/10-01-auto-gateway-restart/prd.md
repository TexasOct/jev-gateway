# 自动网关重启

## 目标

更新已安装的 JEV Gateway 程序后，如果对应运行目录下已有由 JEV CLI 管理的后台网关进程，则自动重启该进程，使其加载新版本代码。未运行的网关不应因更新而被自动启动。

## 背景与已确认事实

- Release 安装器在安装 wheel 并初始化运行目录后结束，不会检查或重启网关。
- CLI 管理的后台进程有 PID 文件和进程所有权校验，入口为 `jev restart`。
- `jev restart` 会停止当前受管理进程（若在运行），然后启动网关；当前停止过程存在 PID 所有权保护。
- 前台运行、容器和外部服务管理器下的进程不属于 CLI PID 文件管理范围。
- `install init` 可选择跳过；更新过程保留已有 `models.json` 和 `.env`。

## 需求

- 在程序包更新成功后，对匹配目标运行目录且由 `jev` 管理的运行中网关执行自动重启。
- 仅当更新前网关已在运行时才重启；fresh install 不自动启动网关。
- 重启必须沿用现有进程所有权校验，不得向未经确认归属的 PID 发送信号。
- 重启失败应给出清楚错误，且不得把安装成功呈现为更新及重启均成功。
- 更新后启动网关时等待健康检查通过，再报告重启成功。沿用 `jev start` 的默认等待时间 10 秒；健康检查失败或超时应报告重启失败。
- 保持现有配置和记录，不因重启流程覆盖或删除它们。
- `--no-init` 仅跳过配置初始化，仍对更新前已运行的受管理网关执行自动重启。

## 范围

本任务仅涵盖官方 Release wheel 安装器更新流程。显式源码 `--ref` 安装、本地开发安装脚本 `scripts/install-local.sh`、容器更新以及 launchd/systemd 等外部服务管理不纳入本次范围。用户选择了此前建议的选项 1。

## 验收标准

1. 更新前目标运行目录没有正在运行的受管理网关时，更新完成后不启动网关。
2. 更新前目标运行目录有正在运行且所有权校验通过的网关时，更新后该进程被停止并启动新版本。
3. 目标进程 PID 未通过现有所有权校验时，不向该进程发送信号，更新流程报告无法自动重启并提供手动处理提示。
4. 安装或 wheel 校验失败时不执行重启。
5. 更新和重启后，已有 `models.json`、`.env`、记录数据库保持不变。
6. 自动重启覆盖成功、未运行、PID 不可验证、停止超时和启动失败等测试情形。
7. 使用 `--no-init` 时，配置初始化仍被跳过，已运行的受管理网关仍自动重启；未运行的网关不自动启动。
8. 重启仅在健康检查通过后报告成功；健康检查最多等待 10 秒，超时或失败须报告重启失败。
