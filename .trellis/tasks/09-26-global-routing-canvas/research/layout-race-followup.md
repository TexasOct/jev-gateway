# Layout write race and scroll lock follow-up

An independent browser review reproduced two issues in the earlier source tree: a rejected layout PUT racing a second node drag could snap the active preview to the previous saved layout, and wheel scrolling during pointer capture could change the node's effective pointer delta. See `final-review.md` for the exact pre-fix scenario and fixture values.

The frontend now uses a serialized `createLayoutWriteQueue` in `canvas.ts`, with generation/revision reconciliation and rollback-before-retry sequencing. `RoutingCanvas.tsx` clears an active gesture and releases capture before restoring the last saved layout after a PUT failure. Queued writes from a failed generation are invalidated. Deferred-promise tests in `layout-race.test.ts` cover failure with newer queued revisions, checkpoint updates, stale saved/failed completions and retry ordering.

Node drag captures its initial canvas scroll offset. During a moved gesture, a non-passive wheel listener prevents native scrolling and the scroll handler restores captured offsets if a scroll event occurs. A trailing corrected scroll is ignored after release. `layout-race.test.ts` covers the pure scroll lock and gesture displacement at 0.5×, 0.75×, 1× and 1.75× zoom.

Post-fix checks: frontend lint passed with four existing `i18n.tsx` warnings, 112 frontend tests passed, Vite/TypeScript build and bundle freshness passed, 589 Python tests passed, and Pyright reported no errors. The isolated native mouse script passed eight node drag/reload cases plus nonzero zoomed viewport restoration and read-only no-mutation checks. A second isolated Chromium replay then held the first layout PUT, started a rule drag, returned HTTP 500, confirmed the active drag was released and both nodes returned to their last saved positions, verified that late movement emitted no PUT, and completed a fresh retry successfully. The wheel replay sent a cancelable wheel signal and a deterministic scroll-offset change during pointer capture; the viewport remained locked, the node followed the expected pointer delta, and the scrollport moved normally after pointer-up. Neither case called a policy endpoint. Test harness limitations: native wheel delivery to the scrollport was unreliable, so a controlled scroll-offset change was used to exercise the lock; no browser wheel event was used after release to confirm OS/trackpad behavior. No backend contract was changed.
