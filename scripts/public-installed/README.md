# Public installed acceptance preparation

This directory prepares hosted acceptance of the public v0.1.3 installer and its exact final wheel. Local preparation is static. The independent final tag/public byte verdict is an input; these files do not claim installed runtime success or close RL1.

Metadata capture and classification share a component guard. The trusted prefix may retain its platform lexical spelling, but location, dist-info roots and every component beneath that prefix must be free of symlinks before metadata content is read. Traversal uses lazy directory iterators, checks components before descent and stops at the 512-entry bound without collecting an entire tree. The owned RECORD is retained first so later traversal/read failures still leave useful partial evidence.

The hosted observer records started, completed and failed state. Unexpected exceptions retain operation and command context and mark the observer failed. Cleanup requires a successful observer completion as well as thread termination; a fatal or unknown dead-thread state cannot be reconciled by a process exit. Raw process errors and exact native-closure reconciliation remain separate evidence.

The hosted uv version is pinned to 0.13.0. Its [local-wheel producer](https://github.com/astral-sh/uv/blob/4ecd0eff2a81e3ffdcd7cfee10d08936e4747c17/crates/uv-distribution/src/distribution_database.rs) and [metadata writer](https://github.com/astral-sh/uv/blob/4ecd0eff2a81e3ffdcd7cfee10d08936e4747c17/crates/uv-install-wheel/src/wheel.rs) define the specific `uv_cache.json` contract. The classifier requires the compact local-wheel CacheInfo serialization, with its Unix timestamp bound to the actual input wheel's ctime, null commit/tags and empty environment/directory maps. RECORD hash/size and owned-path checks still apply. The post-test-dependency probe reuses the initial verified origin's input timestamp because the installer's temporary wheel has been removed.

Before classification, probes retain raw installed RECORD and the complete bounded dist-info inventory, including actual cache bytes, hashes, modes and paths. A failed probe writes partial diagnostics and preserves its cause; it produces no complete origin. The observer records uv and probe exits separately and promotes a staged probe receipt to an origin only after the direct-URL/input join succeeds. Hosted process observations identify the failing operation, PID/create-time and command context. Raw errors remain in the history; only an exact retained Popen identity with an actual native exit can reconcile an observation. Unresolved observations and cleanup errors still fail acceptance. Run 37985815672 did not capture cache contents or the failing process operation. The next attempt must supply its own bytes and process diagnostics.

The manually dispatched workflow is `.github/workflows/public-installed-013.yml`. [GitHub requires the workflow to exist on the default branch before manual dispatch](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow). After independent review and scoped commit, the parent first places the accepted helper commit on default `main`, pushes it and verifies its exact SHA and workflow registration. The parent then dispatches the registered workflow with `gh workflow run public-installed-013.yml --ref <supported-preparation-ref>`, using tag `v0.1.3`, source `4d56e438e2f817115e65f9c47519f9adc62d41c1`, and producer run `37967881650`. Preparation and product refs stay separate; the published tag/source and two pending main status drafts retain their existing scopes. Placement, push, verification and dispatch belong to the parent. The workflow checks out the preparation and signed product source separately and executes on both ordinary Ubuntu and macOS hosted runners. It has read permissions and uploads evidence only.

The runner command is:

```sh
python preparation/scripts/public-installed/driver.py \
  --source "$GITHUB_WORKSPACE/signed-source" \
  --work-dir "$RUNNER_TEMP/public installed acceptance-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}" \
  --tag v0.1.3 \
  --expected-source 4d56e438e2f817115e65f9c47519f9adc62d41c1 \
  --producer-run 37967881650
```

The driver refuses execution outside an ordinary GitHub hosted runner or outside its private temporary directory. It checks producer attempt/jobs/artifact, annotated tag, public release and current latest before any installer runs. Four downloaded public files must match pinned IDs, sizes and SHA-256 values, exact checksum sidecars, the final tag artifact ZIP and its extracted bytes. The current latest installer must match the pinned tag installer. The source installer stamped with the final tag must match the public script. A changed latest release or expired producer artifact stops acceptance and preserves the attempt.

Installation uses the verified public installer with separate tools, executable, state, cache, Python, runtime, temporary and unrelated working directories. An external uv observer checks each actual wheel input immediately before forwarding the unchanged uv arguments. It joins that path to installed `direct_url.json`, without placing observer data into install state. Every successful install gets a separate installed interpreter receipt: Python 3.12, exact `sys.prefix`, distribution and module locations, import finders, existing `.pth` hashes, all package bytes and set membership, static bytes, metadata/license bytes and all wheel RECORD entries. The 94 package files include 42 static files; there are 52 other package files, 100 wheel file members and 100 wheel RECORD rows, of which 99 carry hashes and one is the unhashed RECORD self-row. Complete installed RECORD rows and actual hashes/sizes are retained, with generated metadata, entrypoints and bytecode classified separately. Unclassified additions, escaped resolved paths and invalid declared hashes/sizes fail acceptance. Dependency distributions and their recorded files must resolve under the owned prefix; receipts retain available direct URLs or explicit absent index origins. No `.pth` file is authored.

The driver attempts smoke diagnostic retention after every original smoke outcome. Native failure and timeout remain primary. A separate retention receipt binds that command, preparation/source/run/input identities and every bounded source file's actual hash, size and mode. Original `checks.json`, command 19 and nested logs are copied under uploaded `evidence/original-smoke/` with the smoke's existing synthetic-secret redaction plus collected runtime credential/token values. Owned runtime model documents and logs receive the same sanitization. Credentials, dotenv, PID/install state, database bytes and other runtime files contribute bounded hash/stat diagnostics only; their content is not uploaded. An absent install-state file is explicitly recorded at the snapshot. Missing evidence, aliases, unsupported types, budget or copy errors leave completion false. A retention failure also fails a successful native smoke; it cannot replace or convert a native smoke failure. A failure-time file snapshot does not prove preservation across a repeat installation.

Observer diagnostics may retain a parent PID from an already observed process, without collecting argv or expanding the scan/signal scope. That PID has no parent birth or native-exit proof. Unmatched observations remain blocking under the exact existing native Popen closure and successful observer-completion gates. The driver has no retained Popen handle for a detached server owned by a short-lived installed CLI; source start/status/stop or an empty survivor list cannot supply its native exit.
