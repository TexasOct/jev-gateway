# JEV Gateway 0.1.9

This release adds agent-consumable model limits and cache usage evidence, and
explicit controls for external decision routing.

## Model limits and cache usage

- Protected `GET /v1/jev/models/metadata` lists active concrete models with
  `context_window` and `max_output_tokens`. Unknown limits remain null; dynamic
  strategy names are not assigned a fixed window.
- Chat responses expose the selected model's limits through
  `X-JEV-Context-Window` and `X-JEV-Max-Output-Tokens`; unknown values use `unknown`.
  OpenAI-compatible `/v1/models` and response bodies retain their existing shape.
- Supported OpenAI and Anthropic cache-read/cache-write usage is retained in
  nullable outcome evidence with backward-compatible SQLite column migrations.
  Null or unparseable cache counts remain unknown; explicit zero is preserved.
  Cache tokens still occupy context; existing cost calculations are unchanged.

## External decision routing

- The supplier console provides explicit enable/disable controls and explains
  missing suppliers or credentials. Enabling uses the managed revision,
  validation, activation and rollback transaction. Adding a supplier alone does
  not enable external calls.
- Each strategy can select one configured decision provider. The supplier owns
  its model, endpoint, protocol and credential. Selection is exclusive; failure
  uses the strategy fallback. Clearing selection restores legacy default ordering
  and provider failover.
- Selecting a provider still respects the global decision switch. Existing
  disabled configurations and configured fallback semantics are preserved.

## Integration boundary

The gateway exposes information that local-agent adapters can consume. It does
not provide a product-owned Pi runtime compaction extension or direct Claude
Code/Codex configuration writers. See [agent integrations](../agent-integrations.md)
for ownership and update-timing limits.

Python 3.12+ remains required. Installed wheels include the Dashboard and need no
Node.js. Resolved dependencies are unchanged by the version bump. Publication
does not alter operator configuration or enable a missing decision supplier.
