第一次 Esc 收起菜单，第二次 Esc 处理模型弹窗

待确认的是菜单展开时的关闭顺序。模型弹窗里的“工具调用”使用浏览器原生下拉菜单。菜单展开后，先按一次 Esc：菜单应收起，弹窗、字段值和当前焦点应保留。

本页复用当前源码中的真实 ModelDialog、ModelFields、NativeSelect 和 Radix Dialog。示例数据与保存回调只在页面内存中运行，不连接网关或写入配置。纯 HTML 对照位于下方。建议将窗口展开到 1320px 以上，便于同时查看弹窗与左下角状态；窄屏会隐藏浮动状态板，记录仍会保留。

预期关闭顺序

场景第一次 Esc（菜单展开）第二次 Esc（菜单已收起）
没有修改字段菜单收起；弹窗保留；焦点在下拉框；字段值不变弹窗关闭；焦点返回打开按钮
已经修改字段菜单收起；弹窗和草稿保留；不出现放弃确认弹窗保留并出现放弃修改确认；“继续编辑”应保留草稿
保存中（补充边界）字段禁用，不能打开菜单Esc 不关闭弹窗

操作真实模型弹窗

  1. 打开干净草稿。页面会先定位到“工具调用”字段。
  2. 用鼠标点击下拉框，确认屏幕上真的出现“未知 / 支持 / 不支持”选项。只获得焦点或看到向下箭头不算展开。
  3. 按一次实体键盘 Esc，观察菜单是否收起。检查弹窗仍在、字段值没变，焦点仍在下拉框。
  4. 再按一次 Esc，检查弹窗关闭后焦点是否回到原打开按钮。
  5. 重试“未保存草稿”：先修改显示名称，再滚动到“工具调用”打开菜单。第一次 Esc 不应出现放弃确认；第二次 Esc 才出现确认。选择“继续编辑”，检查修改还在。

纯 HTML 原生菜单对照

先关闭模型弹窗，再操作这个原生 select。它没有 React 事件处理，也没有 Radix 或外层弹窗。展开菜单后按一次 Esc，应收起菜单并保留字段值。

记录本次人工观察

勾选项由操作人确认。原生菜单可能消耗 Esc，网页未必能收到 keydown；日志里没有 Esc 不代表没有按键。本页不会自动把 E1 标为通过。
